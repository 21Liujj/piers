## 【新增页 2】创新点二：基于全景位置的跨视场 Memory 按需分配

**插入位置**：新增页 1 之后

**标题栏文字**：创新点二：基于全景位置的跨视场 Memory 按需分配　　编号：02

**左侧小标题**（红字）：问题诊断：按特征范数排序 ≠ 按重要性排序

**浅蓝框**（一行，加粗蓝字）：
```
MTC 压缩 → 特征范数排序 → Top-K 取 K 个 token → Memory Attention
```

**左表**：
| 实测区域 | token 平均基础分 | 含义 |
|---|---|---|
| 极区 polar | 0.960 | 投影畸变严重，分数虚高 |
| 赤道区 equator | 0.489 | 正常区域，分数偏低 |
| 接缝区 seam | 采样中为 0 | 接缝上下文进不了 Memory |

**表下红字加粗**：
结论：极区畸变 token 因数值偏大挤占预算，真正该保留的少类与接缝 token 反被挤掉。

**右侧小标题**（红字）：方法：三条路由，同一 token 预算

**右表**：
| 路由 | 机制 | 保留对象 |
|---|---|---|
| boundary_guarded | 12.5% 配额保边界 token | 语义边界 |
| class_aware（主推） | 15% 配额保稀有类 | 少类语义 |
| cams | 按与当前 FoV 邻接/重叠检索 | 空间相关上下文 |

**浅绿框**：
```
关键性质
三条路由在同一 token 预算下比较，sum(K_j) = 512 × J 严格守恒；只变选择规则，不变算力。
```

**底部通栏**：
主推 class_aware 的理由：红绿灯、交通标志、杆子、墙面等稀有类面积小、语义占比低，但在 mIoU 中每类权重相同。特征范数排序对它们没有区分度，朴素压缩会直接压塌。类别感知配额用「先保底、再补齐」的方式，在总预算不变的前提下，把稀缺名额定向投给稀有类。

各位老师好，我是刘嘉俊，我的开题题目是《面向文本指定目标的高效全景图像语义分割算法研究》。我主要从四个方面汇报。

### 【第2页｜目录】翻页，不讲。

### 【第3页｜PART 01】翻页，不讲。

### 【第4页｜研究背景】35 秒

先说研究背景。

随着自动驾驶、机器人对 360 度场景感知的需求增加，全景图像能覆盖完整的周围环境，而像素级语义分割是后续场景理解的重要基础。

但全景图像有几个特殊的结构问题。一是 ERP 投影会带来位置相关的畸变，左右边缘在真实空间里是首尾相连的；二是实际处理要切成局部视场，目标可能被视场边界截断；三是全景图像的像素级标注成本很高，透视图像迁移过来又有明显的域差异。

另外，现有固定类别的无监督域适应只能对预设类别做预测。如果用户希望用一句自然语言指定"想找什么"，就还需要目标定位、跨视场关联和全景掩码融合这一整套能力。

### 【第5页｜选题依据】25 秒

我的工作建立在两类技术基础上。一类是 OmniSAM，用 FoV 序列和 SAM2 的 Memory 关联跨视场信息；另一类是 Grounded SAM，用 Grounding DINO 按文本定位目标，再由 SAM2 生成掩码。

但要把它们真正用到全景场景，还必须解决坐标回映、重复候选关联、跨接缝融合，以及 Memory 计算开销这四个问题——这四点正好对应我后面的三个创新点。

### 【第6页｜PART 02】翻页，不讲。

### 【第7页｜研究内容】25 秒

我的总体目标是：面向全景图像实现文本指定目标的完整分割，同时兼顾分割质量和计算效率。

具体开展两条实验路径。一条是文本指定目标分割，是本课题的主要应用主线；另一条是延续 OmniSAM 的全景语义分割 UDA，用来研究和验证跨视场 Memory、环形边界这些通用模块。两条路径共享 FoV 划分和 ERP 坐标映射，统一做实验评价。

围绕这两条路径，我设计了三项研究内容。

### 【第8页｜技术路线】20 秒

技术路线概括成四步：先做文献调研和基线复现，分别复现 OmniSAM 和 Grounding DINO 加 SAM2；然后完成双任务建模和全景适配；在此基础上重点研究高效跨视场 Memory 和环形空间优化；最后通过对照实验、同预算消融和失败案例分析做迭代验证。

### 【第9页｜创新点一】30 秒

第一个创新点是文本与全景语义协同的目标分割。

基本流程是：输入全景图像和文本查询后，先划分局部 FoV，在各 FoV 里用 Grounding DINO 做文本条件定位，再用 SAM2 生成目标掩码，最后映射回 ERP 全景坐标。

真正要研究的是全景环境下的跨视场关联。同一个目标可能同时出现在多个重叠 FoV 里，也可能刚好被首尾接缝截断。所以要研究查询感知的候选关联与融合，并在固定推理预算下优先观察定位不确定或容易被截断的区域。

这个方向目前代码已经跑通，实验还在进行中。

### 【第10页｜切入点：Memory】30 秒

在讲具体研究内容之前，我先说明我为什么把 Memory 机制作为整个课题的切入点，这也是三个创新点的共同理论依据。

OmniSAM 处理全景图，是把全景切成一系列局部视场，靠 Memory 把历史视场的信息传给当前视场。也就是说，Memory 是全景分割的上下文总线——跨视场语义关联、小目标保不保得住、接缝上下文够不够，全都走这条路。

更关键的是，Memory 是唯一贯穿训练和推理全过程的瓶颈：伪标签生成、目标域自训练、验证推理，读的都是同一份 Memory。优化它，收益体现在整条链路上。

而且 Memory 的读写规则本身是可设计的。原始做法是无差别全量存储、按特征范数取 Top-K，不考虑位置也不考虑类别。我引入全景空间位置约束和类别重要性先验，就得到"按需分配"这条新通路。

### 【第11页｜创新点二·方法】50 秒

接下来是第二个创新点，也是我目前完成度最高的一个：基于全景位置的跨视场 Memory 按需分配。

先看问题诊断。OmniSAM 的 Memory 读取是三步：先 MTC 压缩，然后按特征范数排序，最后取 Top-K 参与注意力计算。这个过程是无差别的——不看 token 在全景空间的位置，也不看它属于什么类别。

我们实测了 token 的区域分布，发现一个反直觉的现象：极区 token 的平均基础分是 0.96，赤道区只有 0.49，接缝区在采样里是 0 个。也就是说，按特征范数排序根本不等于按重要性排序——投影畸变严重的极区，特征数值天然偏大，把预算挤走了；真正该保留的少类和接缝上下文反而被挤掉。

我们的做法是总预算不变，改选择规则，实现三条路由：边界保护、类别感知、空间邻接检索。主推类别感知，留 15% 配额保稀有类。

强调一点：三条路由都在完全相同的 token 预算下比较，总数严格守恒，所以精度差异只能来自选择规则，不是算力差异。

### 【第12页｜创新点二·主结果】60 秒

这是创新点二的主结果。

先看基线复现。OmniSAM 论文报 60.23，我们用同一个 checkpoint、同一套流程在 DensePASS 100 上复现出 60.46，高了 0.23，说明我们的评测口径和原论文对齐了，后面所有对比都建立在这个基础上。

然后是主结果：Memory token 从 32768 压到 2048，十六倍压缩。整体 mIoU 只掉 0.16，但平均类别准确率涨了 0.35。稀有类更明显：红绿灯 30.06 涨到 30.69，交通标志 26.03 涨到 26.69。

为什么稀有类会涨？因为它们面积小、语义占比低，但 mIoU 里每个类权重一样。均匀采样会把它们压没——朴素池化那一列，红绿灯直接塌到 25.84，比我们低 4.2 个点。这就是类别感知配额的价值。

消融上，所有变体都在同一个 2048 预算：类别感知 60.30、边界保护 60.27、朴素池化 60.07、Top-K 59.83、均匀采样 59.80、空间邻接 59.75。只有带类别或结构先验的两条守住了精度。

### 【第13页｜创新点二·效率与演进】55 秒

这一页讲效率和两版演进。

中间版叫 Pano-SMB，做的是 FoV 之间的配额分配——按每个视场的重要性决定给它多少 token，训练期用，8 倍压缩，注意力时间降 55.8%，显存省约 1.2G，精度掉 0.24。

最终版往前推了一步，变成 FoV 内部的 token 级选择，也就是刚才那三条路由。作用位置从训练期挪到推理期，压缩比从 8 倍提到 16 倍，精度代价从掉 0.24 变成只掉 0.16、平均准确率还涨 0.35。

右边这块我要诚实报告一个反直觉的结果：压缩的是 token 数，不是端到端延迟。类别感知要额外算类别掩码和配额，100 张反而比原版慢 21%。真正省时间的是朴素池化和均匀采样，但它们的稀有类塌了。所以这个模块的价值是"用可忽略的精度代价换记忆空间和显存"，不是加速。很多论文会把 token 减少直接说成加速，我这里不想这么写。

### 【第14页｜创新点二原文页】15 秒

这一页是创新点二在工程上的落地。核心是三条选择路由，同预算严格守恒，配合 token 区域诊断工具，形成完整的消融体系。

### 【第15页｜创新点三原文页】20 秒

第三个创新点是接缝区域按需补看。由于 ERP 图像首尾相连、常规视场容易在接缝处截断目标和语义边界，我提出先让跨接缝视场看到左右两端的连续内容，再根据接缝附近的预测不确定度和边界截断情况，在固定额外推理预算内选择需要补看的位置。补看结果映射回原图后，只在实际重叠区域内结合预测可靠性融合。

### 【第16页｜创新点三·从固定到按需】55 秒

这里我要讲清楚它和前期工作的关系。

前期我已经实现并验证了固定宽度 SCM。机制是在数据集层做环形 padding，让模型滑窗时能看到跨边界的连续上下文，推理后裁回原尺寸。消融很干净：pad 从 256 加到 1024，mIoU 从 60.51 单调涨到 60.84，涨了 0.33；其中 traffic sign 从 26.07 涨到 31.11，涨了 5 个点。

这既证明"接缝上下文不足"假设成立，也暴露固定做法的局限——不管这张图的接缝有没有问题，都补同样宽度、花一样的钱。

所以我的创新是在固定 SCM 之上加一层按需：先给接缝附近打分，不确定的地方才值得补看；补的是真跨过接缝的连续窗口，用环绕裁剪，不是拿假整宽框糊弄；融合只发生在真实重叠的区域。B 等于 0 时一个窗都不加，输出和基线逐比特一致。

百张五个变体都跑完了。结论如实说：方向是正的，但增益只有千分位，因为基线 18 窗已经把接缝处理得不错。另外按需选窗和均匀加窗结果完全一样——候选池就两个以缝为中心的窗口，两种策略必然选到同一组。按既定口径，这算该预算下按需无增益，我如实写进论文。B 等于 0 的退化校验通过，可以作为正确性证据。

# 第三部分：预期问答准备

## Q1（最可能被问）：你的 Memory 优化到底省了多少？加速了吗？

要分两个层面看。Memory token 数从 32768 压到 2048，是 16 倍压缩，显存和 Memory Attention 的计算量确实降了。但端到端 wall time 我实测反而慢了 21%——因为类别感知要额外算类别掩码和配额，收益被吃掉了。真正省时间的是朴素池化，但它把稀有类压塌了，红绿灯掉到 25.84。

所以我的结论是：这一版的核心价值是"精度—记忆空间"的权衡，不是加速。要拿到真加速，需要把类别掩码预计算缓存下来，或者走近似实现，这正是下一步的工作。我特意不做"token 数减少 = 加速"这种说法，因为那不成立。

**如果老师追问"那你为什么还要做"**：因为 Memory 显存是全景分割部署的硬约束，在显存受限的场景下 16 倍压缩能决定模型跑不跑得起来，这比快 20% 更关键；而精度代价只有 0.16 且稀有类还涨了。

## Q2：创新点三的增益只有千分位，算不算有效？

我按事先定的口径来判断：如果同预算下按需打不过均匀补看，就记为"该预算该数据下无增益"，不追加预算、不换 band 宽度重跑。这次确实 adapt 和 uniform 完全一致，原因是候选池只有两个以缝为中心的窗口，两种策略必然选到同一组。

但前期固定 SCM 的结果是 traffic sign +5.04，说明接缝缺陷本身是真实且严重的。我的判断是：DensePASS 的接缝问题已经被 18 窗基线处理得比较干净了，按需的收益要在接缝破坏更严重的数据上才显现。所以我在论文里的定位是：按需补看是一个有正确性保证（B=0 严格退化）的自适应扩展机制，在当前数据上收益有限但不损害，负结果也是结论。

**如果老师认为这是"没做出来"**：我更倾向于如实报告这个结果并分析清楚原因，而不是调参把它做成正数。这也是我给整个课题定的实验纪律。

## Q3：创新点一还没有结果，课题主线靠什么支撑？

创新点一是主线应用方向，目前代码链路已经全通：真实 Grounding DINO 加 SAM2 后端验收通过，T0 整图直喂和 T1 切片加回贴加跨窗关联两种模式，都在 DensePASS 100 的 800 条查询上跑完了真实推理。差的是最后一步评测对比——之前 worker 只落盘了框没落盘掩膜，评测链路缺一个输入，我已经补上掩膜落盘的代码。

关于课题的支撑，我的判断是：Memory 机制这条线是可以独立成立的，它已经完整验证并有正向结果。创新点一和它共享同一套全景几何和坐标回映基础设施，也就是说即使文本分支的增益不如预期，课题在"高效全景分割"这个方向上仍有扎实产出。

后续 GPU 恢复后，优先把 T0/T1 的 per-query IoU 对比跑出来，同时推进 T2 语义引导重排和 U1 伪标签修订，形成双向闭环。
